# LiveKit M0 test deployment (Dar) — FEATURE FLAGGED, NOT PRODUCTION

Temporary test instance used to validate live audio quality **before** building the in-house meetings product (docs/22, docs/runbooks/livekit-m0.md). It is isolated from the product: separate service, separate install path, no product routes changed.

> **Status: BLOCKED for the live host (owner actions).** This is a spike. Installing it, opening media ports 7881/tcp + 7882/udp, and **closing those ports again on the live host** are owner actions — agents must not run them against production/staging. See "Owner actions" below.

## What runs

| Part | Where | Notes |
|---|---|---|
| livekit-server v1.13.11 | `/usr/local/bin/livekit-server` + `dar-livekit.service` | binds signaling to 127.0.0.1:7880 |
| RTC | UDP 7882 (mux) + TCP 7881 | **closed by default**; only `--open-media-ports` opens them |
| WSS signaling | `/livekit/` in the Nginx site | `https://<deployment-host>/livekit`; snippet is merged by hand |
| Test page | `/var/www/live-test/` → `/live-test/` | **opt-in** `--with-test-page`; imports livekit-client from a public CDN |
| Tokens | `/usr/local/bin/dar-live-token ROOM IDENTITY NAME TTL_HOURS` | HS256, reads `/etc/dar/livekit.env` |
| Config/secrets | `/etc/dar/livekit.yaml`, `/etc/dar/livekit.env` (640 root:livekit) | never committed |
| UDP buffers | `/etc/sysctl.d/99-dar-livekit.conf` | 16MB rmem/wmem |

## Install (explicit feature flag + checksum verification)

```bash
# Refused without --enable-livekit-test (or LIVEKIT_TEST_ENABLED=1):
sudo bash deploy/livekit/install-livekit-test.sh --enable-livekit-test

# Optional test page for the M0 checklist only (public CDN import - never production):
sudo bash deploy/livekit/install-livekit-test.sh --enable-livekit-test --with-test-page

# Optional: open the media ports (owner decision, see below):
sudo bash deploy/livekit/install-livekit-test.sh --enable-livekit-test --open-media-ports
```

The installer downloads `livekit_<version>_linux_amd64.tar.gz` only after verifying its SHA-256 against a **pinned digest** (`v1.13.11` is pinned in the script; any other version requires `LIVEKIT_SHA256=<digest>` or the installer fails closed — no unverified download). It is idempotent: the binary is kept when already installed and existing API keys are preserved.

The Nginx WSS locations are **not** generated by `deploy/setup-nginx.sh`; merge `deploy/livekit/nginx-livekit-locations.conf` into the vhost by hand, then `sudo nginx -t && sudo systemctl reload nginx`.

## Issue a token + link

```bash
ROOM="dar-test-$(openssl rand -hex 3)"
TOKEN=$(sudo /usr/local/bin/dar-live-token "$ROOM" owner 'المالك' 12)
echo "https://<deployment-host>/live-test/#room=$ROOM&t=$TOKEN"
```

## Test checklist (two devices, different networks)

1. Open the link on two devices (Chrome/Edge desktop + Android Chrome; iOS Safari only if a real device is available).
2. Join room → press "تشغيل الصوت" (autoplay gesture) → unmute mic on one side and speak.
3. Listen for dropouts/gaps on the other side; switch one device to mobile data to test NAT/TURN need.
4. Try "مشاركة الشاشة" while speaking (load test equivalent of the recorder failure case).
5. If a device on mobile data fails to connect while WiFi works → UDP is blocked, TURN is required (next step).

## Owner actions (BLOCKED for agents on the live host)

1. **Install/uninstall** the spike (`--enable-livekit-test`) — owner decision only.
2. **Open media ports** if the firewalled host needs them: `sudo ufw allow 7881/tcp && sudo ufw allow 7882/udp`.
3. **Close production ports 7881/7882 after the spike** — required cleanup, explicitly an **owner action** (agents are BLOCKED from touching the live firewall):
   ```bash
   sudo ufw delete allow 7881/tcp
   sudo ufw delete allow 7882/udp
   sudo ufw status numbered   # verify 7881/7882 are gone
   ```
4. **Remove the test page route** from the Nginx vhost (it is not in `setup-nginx.sh`; remove the hand-merged `/live-test/` block) and delete `/var/www/live-test/index.html`.
5. Rotate `/etc/dar/livekit.env` keys if links/tokens may have leaked.

## Rollback / removal

```bash
sudo systemctl disable --now dar-livekit
sudo rm -f /etc/systemd/system/dar-livekit.service /usr/local/bin/livekit-server \
             /usr/local/bin/dar-live-token /etc/dar/livekit.yaml /etc/dar/livekit.env \
             /etc/sysctl.d/99-dar-livekit.conf
sudo rm -rf /var/www/live-test
# remove the hand-merged /livekit/ + /live-test/ Nginx locations, then:
sudo nginx -t && sudo systemctl reload nginx
# owner action: close the media ports (see above)
sudo ufw delete allow 7881/tcp; sudo ufw delete allow 7882/udp
```

## Security notes for the test

- The page is unlisted but public when enabled, and it loads third-party JS from jsdelivr. Do not publish links; do not enable it on production.
- The API key/secret stay on the host in `/etc/dar/livekit.env`; rotate by deleting the file + restarting (config is regenerated from env on install).
- This is a spike: no TURN, no recording, no auth integration, no monitoring/alerts yet.
