# ADR-0004 — تأجيل اللغة الإنجليزية

**Status:** Accepted
**Date:** 22 Nov 2026
**Decider:** مالك الدار
**Related:** `docs/01-business.md` §8؛ `docs/02-architecture.md` قرار رقم 20؛ `docs/04-engineering-standards.md` §3.5؛ `docs/05-roadmap.md` Phase 5.1؛ `docs/06-operations.md` §13

## Context

قرار قديم في وثائق المشروع كان ينص على دعم العربية والإنجليزية (Arabic + English) مع `next-intl` وواجهة Next.js. الواقع:

- الواجهة الحالية React 19 + Vite + TypeScript، وقرار Next.js ملغى (22 Nov 2026).
- لا يوجد أي نظام i18n ولا ملفات ترجمة؛ الواجهة عربية RTL بالكامل.
- المستخدمون الحاليون (مالك، إدارة، معلمات، مشرفات) عرب، والإنجليزية لا تُستخدم فعليًا.
- البناء الآن على مرحلتين: Docs Reset ثم أمان النشر/الـBackup، ولا توجد حاجة تشغيلية للإنجليزية.

## Decision

1. **اللغة الإنجليزية مؤجلة** بدون تاريخ محدد، وليست في نطاق MVP الحالي.
2. اللغة العربية (RTL) هي لغة الواجهة الوحيدة الآن.
3. لا يتم إدخال `next-intl` أو أي تبعية i18n في هذه المرحلة؛ ولا يُشترط أي بنية ترجمة مسبقة.
4. عند تنفيذ الإنجليزية لاحقًا: تُختار مكتبة مناسبة للواجهة الحالية (Vite SPA) بقرار مكتوب، وتُستخرج النصوص من الواجهة العربية، وتُطبق على الحد الأدنى المطلوب (واجهات التشغيل الأساسية أولًا).
5. الوثائق التي تصف «عربي + إنجليزي» كحالة حالية تُحدَّث إلى «عربي الآن، إنجليزي مؤجل».

## Consequences

- معايير القبول والـDefinition of Done لا تتضمن إنجليزية أو i18n في هذه المرحلة.
- الجهد الموجَّه للواجهة يذهب إلى تجاوب لوحة الإدارة بالكامل على الموبايل، ثم بوابات المعلمة/المشرفة، بدل نظام ترجمة غير مطلوب تشغيليًا.
- لا تكتب نصوصًا مزدوجة (عربي/إنجليزي) داخل المكوّنات؛ العربية فقط حتى يصل قرار التنفيذ.
- أي طلب لاحق للإنجليزية يُفتح كمرحلة مستقلة بقرار مالك، مع تقدير أثر على كل شاشة وتقارير PDF.
- `docs/02` و`docs/04` و`docs/05` و`docs/06` تحتاج تحديث تلك الإشارات عند Docs Reset.
