## Risks

- **إبطال جلسات الأدمن مرة واحدة** بعد نشر ADR-0006 (تغيّر purpose strings) — متوقع وموثّق؛ يلزم إعادة تحميل الصفحة بعد migration 026 أيضًا لظهور صلاحيات meet في الـSPA.
- **جسر الجلسة لم يُختبر end-to-end** محليًا (لا DB/legacy يعملان) — أول تحقق سيكون على staging/الإنتاج؛ البديل الفوري هو إبقاء الوحدة خلف صلاحيات meet.* (لا تُمنح لأحد قبل التحقق).
- **OAuth غير مختبر**؛ وفي وضع Testing تنتهي صلاحية refresh token بعد 7 أيام → يجب نشر التطبيق في Production mode.
- **الاعتماد على شكل استجابة Google** (أسماء الحقول) — أي تغيير يُكتشف عند أول مزامنة فعلية؛ الأخطاء تُسجَّل وتُظهر في `last_error_message`.
- **حجم أحداث التقويم**: كل occurrence صف؛ مع تقويم مزدحم ونافذة 90 يومًا قد ينمو الجدول بسرعة. لا retention بعد.

## Decisions

- **Calendar API بلا حزمة رسمية:** `Google.Apis.Calendar.v3` غير متاح في الـfeed المغلق؛ العقد صغير (3 استدعاءات) فكُتب على `HttpClient` ومُغطى باختبارات للـstate/التشفير. موثق في ADR-0007.
- **الكوكي المقروء هو نفس كوكي الـlegacy** (لا جلسة ثانية ولا CORS): ADR-0006، مع الحفاظ على `SameSite=Strict` والتحقق الخادمي من `session_version`.
- **نطاق التسجيل على مستوى الحلقة** (`meet_circle_settings`) + تجاوز لكل حدث (`recording_mode`) — يطابق قرار المالك «حلقات مختارة» مع استثناء فردي.
- **`meet.media.view` قابلة للسحب** للمشرفة (قرار المالك 6) — الجسر يقرأ الصلاحيات كل طلب فالسحب فوري.
- **لا حذف تلقائي للـMP4** — العمود `deleted_at/by` + `verified_on_drive` موجودان الآن، والتنفيذ في 3.4.
